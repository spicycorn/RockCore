 RockCore 项目 · GitHub 常用操作命令速查
 所有命令在 PowerShell 中执行；进入项目：cd C:\projects\RockCore
═══════════════════════════════════════════════════════════════

【0】一次性环境修复
─────────────────────────────────────────────
命令：git config --global --add safe.directory C:/projects/RockCore
作用：解决 "detected dubious ownership" 报错（仓库属主与当前用户不一致，
      如仓库由管理员创建）。
场景：换电脑、换用户、或用管理员身份克隆/创建过仓库后，任何 git 命令都
      报属主可疑时执行一次即可，永久生效。

【1】查看当前状态
─────────────────────────────────────────────
命令：git status
作用：列出哪些文件改了、哪些已暂存、哪些未跟踪。
场景：每次提交前后都建议跑一次，确认改动范围符合预期，避免误提交。

【2】完整上传一套（最常用：改代码 → 提交 → 推送）
─────────────────────────────────────────────
命令：
  git add -A
  git commit -m "feat: 本次改动说明"
  git push origin main
作用：add 把所有改动放入暂存区；commit 生成一次本地版本记录；push 上传
      到 GitHub 的 main 分支。
场景：日常开发完成一个功能或修完一个 bug 后。提交说明建议带前缀：
      feat 新功能 / fix 修复 / chore 杂项（版本号、配置）/ docs 文档。

【3】只提交指定文件（不想全量提交时）
─────────────────────────────────────────────
命令：
  git add 路径/文件名
  git commit -m "fix: 说明"
  git push origin main
作用：只把指定文件纳入本次提交，其余改动留在工作区。
场景：同时改了好几处，但只想先上传其中一部分。

【4】拉取远程最新代码
─────────────────────────────────────────────
命令：git pull --rebase origin main
作用：把 GitHub 上的最新提交拉下来，并把本地提交挪到最新提交之后，
      保持提交历史一条直线、没有多余的合并记录。
场景：多人协作，或自己在网页端改过 README 之后，推送前先拉一次。

【5】发布版本（打标签 → 自动打包发布）
─────────────────────────────────────────────
命令：
  cd app
  npm version 1.2.0 --no-git-tag-version
  (Get-Content src-tauri\tauri.conf.json -Raw) -replace '"version":\s*"[\d.]+"', '"version": "1.2.0"' | Set-Content src-tauri\tauri.conf.json -NoNewline
  cd ..
  git add -A
  git commit -m "chore: 发布 v1.2.0"
  git tag -a v1.2.0 -m "RockCore v1.2.0"
  git push origin main
  git push origin v1.2.0
作用：先同步改 app/package.json 和 tauri.conf.json 的版本号，再打 v 开头
      的附注标签并推送；GitHub Actions 收到 v* 标签后自动构建 NSIS 安装
      包并发布到 Releases（含安装包、导入模板、使用说明）。
场景：每次要发新版本时，把命令里的 1.2.0 换成新版本号即可。
注意：标签名必须以 v 开头（如 v1.2.0），否则不会触发自动打包。

【6】删除误打的标签（本地 + 远程）
─────────────────────────────────────────────
命令：
  git tag -d v1.2.0
  git push origin :refs/tags/v1.2.0
作用：删掉本地和 GitHub 上的标签。
场景：标签打错版本号、或触发了错误的自动发布。删完记得同步删掉对应的
      GitHub Release（网页端 Releases → 删除）。

【7】撤销工作区改动（还没 add 的）
─────────────────────────────────────────────
命令：
  git restore 路径/文件名
  git restore .
作用：把文件恢复成最近一次提交的样子，未保存的修改会丢失。
场景：改乱了想放弃某个文件（或全部文件）的本次修改。
注意：此操作不可恢复，重要改动先执行【8】暂存起来。

【8】临时存起改动（stash）
─────────────────────────────────────────────
命令：
  git stash
  git stash pop
作用：stash 把当前未提交的改动收进临时抽屉并还原工作区；pop 把最近一次
      收进去的改动取回来。
场景：改到一半需要紧急切换分支或拉代码，但改动还不值得提交。

【9】分支操作
─────────────────────────────────────────────
命令：
  git switch -c 分支名        （新建并切换）
  git switch main             （切回主分支）
  git merge 分支名            （把某分支合入当前分支）
  git push origin 分支名      （把分支上传 GitHub）
作用：在独立线上开发，不影响 main。
场景：做大功能、做实验性改动时先开分支，完成后再合并回 main 推送。

【10】查看历史
─────────────────────────────────────────────
命令：
  git log --oneline -20
  git log --oneline --graph -20
作用：一行一条显示最近 20 次提交；graph 版带分支图形。
场景：找某次改动在哪、确认自己提交到了哪、回滚前定位版本。

【11】回滚到某个版本（保留历史的安全做法）
─────────────────────────────────────────────
命令：
  git log --oneline -20
  git revert 提交号前7位
  git push origin main
作用：revert 生成一条"反向提交"抵消那次改动，历史不被改写，多人协作安全。
场景：上线后发现某次提交有 bug，需要撤销但别人可能已经拉过代码。
注意：不要用 git reset --hard 回滚已推送到远程的提交，会坑到协作者。

【12】改最近一次提交（说明写错、漏了文件）
─────────────────────────────────────────────
命令：
  git add -A
  git commit --amend -m "新的提交说明"
  git push origin main --force-with-lease
作用：修改最近一次提交的内容或说明；--force-with-lease 是安全版强推
      （远程有别人新提交时会拒绝，避免覆盖他人代码）。
场景：刚 push 完就发现笔误或漏文件，且确定没人基于这条提交继续开发。

═══════════════════════════════════════════════════════════════
 一套标准日常流程（背下来就够用）
─────────────────────────────────────────────
 日常上传：  git add -A → git commit -m "..." → git push origin main
 发布版本：  改版本号 → 提交 → git tag -a vX.Y.Z → push 分支 → push 标签
 拉取更新：  git pull --rebase origin main
