## 2. 判级换算（全部实测，无估算）

现场原始记录两类：**回次级**（回次进尺 L(m)、<10cm 碎屑数 n_f）与**段级**（逐根量测的 ≥10cm 岩心段长度 ℓ₁..ℓₖ，k 即 ≥10cm 段数 n₁₀）。

```
≥10cm 段数   n₁₀ = k（明细表行数）
≥10cm 总长   R   = Σℓᵢ
岩心总段数   n   = n₁₀ + n_f
节理数       J   = n − 1
平均间距     S   = L × 100 ÷ n   (cm)
RQD(%)           = R ÷ (L×100) × 100
(J, S) → IntegrityCriteriaEngine（F.0.4 原引擎）→ 完整性等级
```

交叉校验（导入时执行）：
- 明细段长 <10cm → 红行阻断（明细表只登记 ≥10cm 段）
- R > L×100 → 红行阻断（总长不可能超过进尺）
- 碎屑平均长 (L×100−R)/n_f ≥ 10 且 n_f>0 → 黄行警告（计数与量测矛盾）
- S > 500cm → 黄行警告（疑似 mm 误填，一键换算）
- 全碎回次（无 ≥10cm 段）：明细 0 行、n₁₀=0、n=n_f，正常判级，RQD=0

## 3. 模板定稿（v4 一钻孔一文件 · 录入/成果双表，已生成）

**文件**：`docs/templates/岩心回次统计导入模板.xlsx`（生成脚本 `.gen-template.js`；univer 源文件暂名"岩芯…"，待文件锁释放后改名）

**结构**：**一个钻孔 = 一个 Excel 文件**（建议文件名=钻孔编号，导入时选择目标钻孔）；两个工作表：

| 工作表 | 内容 |
|--------|------|
| 「数据录入」 | 一行一回次（行序=深度序）；手工填：回次进尺(m)* / <10cm碎屑数* / L1–L30(cm) 逐根量测段长；回次号选填 |
| 「计算成果」 | 与录入表逐行对齐：前 10 列公式自动生成（段数/总长/RQD/起点/终点/n/J/S），后 6 列 F.0.2 选填下拉 |
| 「填写说明」 | 规则全文 |

公式口径：`段数=COUNT(L区)`、`总长=SUM(L区)`、`RQD=总长÷(进尺×100)×100`、`起点=上行终点`（首行 0，非 0 起深在导入对话框设置）、`n=段数+碎屑数`、`J=n−1`、`S=进尺×100÷n`。

### 3.1 模板 v4.1 修正（复核表格逻辑与公式后的改动）

| 项 | 原 | 现 | 原因 |
|----|----|----|------|
| RQD 小数位 | `ROUND(...,1)` | `ROUND(...,2)` + 单元格格式 `0.00` | 0.1% 精度偏粗，且与软件重算位数不一致 |
| 平均间距 S | `ROUND(...,1)` | `ROUND(...,2)` + 单元格格式 `0.00` | S 直接决定 F.0.4 判级，边界处 0.1cm 会翻档 |
| 节理数 J | `H-1` | `MAX(0,H-1)` | n=0 时算出 −1，与软件 `Math.Max(0,n-1)` 不一致 |
| 区间起点 | `N(上一行终点)` | `SUM(数据录入!$B$2:$B{上行})`（首行恒 0） | 中间留空行时旧公式把深度重置为 0，整条深度链错位 |
| 示例数据 | 录入表前 5 行示例 + 成果表 K2:P2 示例参数 | 全部清空；示例改写入「填写说明」的自检口径 | 示例行会被连同真实数据一起导入；K2:P2 的示例参数会被用户第一条数据**静默继承**并写进 F.0.2 |
| 计算链 | 依赖公式缓存值 | 清空缓存值 + `fullCalcOnLoad="1"` + 删除 `calcChain.xml` | 只读预览器/查看器不再显示过期数字 |

软件侧同步：`ExcelImportService` 的 RQD、平均间距同样保留 2 位小数，预览表按 `0.00` 显示，保证「Excel 里看到的 = 软件算的」。


**样板数据（已内置并实算验证）**：5 个回次（含 J=0 完整回次、无 ≥10cm 段的全破碎回次两个边界），深度衔接 0→2→3.5→5.5→6.5→8.5m 全部正确。

**导入器原则**：文件对应一个钻孔（对话框内选择，文件名自动预匹配）；读取「数据录入」原始列 + 「计算成果」F.0.2 列（按行对齐）；全部指标由软件重算，公式列仅供现场查看。

## 8. 完整性判定单元核实（F.0.4：按回次还是按 1m？）

### 8.1 现状

判级输入只有两个量，都按**回次**计算：`J = n − 1`（回次内节理条数）、`S = 进尺×100÷n`（回次内平均间距），一个回次 = 一个完整性分段。

### 8.2 核实结论（三条，均有代码/数据依据）

1. **「平均间距」按回次算是成立的。** S 是密度量（长度÷条数），与统计段长无关：2m 回次 8 段 → 25cm，与"每 1m 4 段"等价。回次长度 1~2m 也与规范常用的 1m 测段同量级。
2. **「组数」列被喂错了量——这是判级失准的根因。** 表 F.0.4 的该列是**结构面发育组数**（节理**组数**，地质描述量，取值 1~2 / 2~3 / >3），而软件代入的是**回次内节理条数** `J=n−1`（2m 完整岩也能到 7~8，破碎段可达 40）。量纲差 1~2 个数量级，导致 `J>3 且 S>10` 的组合在表里**一行都匹配不上**，只能落到"只看间距"的兜底分支。实测：进尺 0.5~3.0m × n=1~40 共 200 组常见组合中，**31.5% 走兜底**；进尺 2m、n=8（S=25cm）这类常见完整岩回次全部走兜底。
3. **主表与兜底彼此口径一致，但两者与 `design.md` 7.2 整体差一档。** 兜底 `>95 完整 | >50 较完整 | >30 较完整 | >10 完整性差 | >2 完整性差 | >0 破碎` 中 `>50/>30`、`>10/>2` 两对返回值重复，说明它是照主表手抄的，两者口径相同；而主表 `30~50→较完整`、`10~30→完整性差`、`≤10 仅 <2 才判破碎`，与文档 7.2 的 `30~50→完整性差`、`10~30→较破碎`、`<10→破碎` **整体差一档**。除 95cm 边界有"项目经验调整值"注释外，其余偏移无任何记录，**必须对照规范原文表 F.0.4 重新定档**。

### 8.3 为什么不能改成"按 1m 定段"

模板只记录**每根岩心段的长度**（L1–L30）和**碎屑根数**，**没有每段的深度位置**。把回次内的结构面切到固定 1m 网格只能假设"均匀分布"，属于伪精度；且会破坏"一个回次 = 一条原始记录"的可溯源性。真要按 1m 或按岩体单元判级，正确做法是**在模板里增加逐段深度定位**（或改用孔内电视/图像分段，M3 方向），而不是在现有数据上硬切。

### 8.4 已实施方案（判定表数值一律未动，只改逻辑）

- **自动判级只用「平均间距」**：新增 `IntegrityCriteriaEngine.TryMatchBySpacing`，只按间距查表，「结构面发育组数」不再参与匹配。内置默认表改为 6 行、组数留 `—`，**间距分档与等级映射数值原样保留**。配置文件里的历史默认表会被定向迁移（仅当与内置默认表逐行一致时），用户自定义表不受影响。
- **判级路径唯一**：取消"表匹配失败 → 另走一套间距兜底"的双路径；兜底只在用户把判定表改坏导致无匹配时兜住，且分档与默认表一致。
- **回次 → 岩体段归并**（新增 `RockMassSegmentBuilder`）：**先归并、后判级**。相邻回次平均间距相对差 ≤ 容差（默认 50%）则合并；深度空洞（被排除/阻断的行）、岩质变化为强制分界；不足最小段厚（默认 1.0m）的薄段并入间距最接近的相邻段。段指标用合并口径 `S = 段厚×100÷Σn`、`RQD = Σ合格段长÷(段厚×100)×100`，不是各回次的算术平均。
- **落库形态**：`RunStatistics` 仍一个回次一条（原始记录可溯源），`BoreholeIntegritySegments` 改为一个岩体段一条；导入对话框同时预览两张表。
- **可回退**：`rock_specification.json` 中 `ConfigThresholds.MergeRunsIntoRockSegments = false` 即恢复"一个回次 = 一个分段"；`RockSegmentMinThicknessM`、`RockSegmentSpacingToleranceRatio` 可调。
- 未做（待议）：超长回次的黄行提示、RQD 与 S 明显不匹配的校核提示。

> 归并比较口径的坑：判"能否并入当前段"时必须用**该回次自身间距 vs 当前段间距**，不能用"并入后的均值 vs 当前段间距"——后者会被大段的均值摊薄，实测能把整孔 21 个回次吞成 2 段。

### 8.5 「分段」的专业口径（复核结论）

规范里的**评价单元不是回次，也不是固定 1m，而是"岩体性质相对均一的连续段"（岩体单元 / 工程地质段）**。回次只是钻探取芯的自然单元，属于**采样间隔**，不是评价单元。常规做法分三步：

1. **按回次算指标**（RQD、平均间距、条数/米）——这一步是统计，回次是样本；
2. **把相邻、指标相近的回次归并成岩体段**——段内性质相对均一；段厚一般不小于 1~3m，过薄的按相邻段处理或单列薄层；界线取实测深度；岩性突变、地下水面、断层破碎带、不同岩体单元接触带为强制分界；
3. **对归并后的岩体段判完整程度**，再叠加 F.0.2 各因素按**工程段**（洞室桩号段 / 岩体单元）给围岩类别。

因此软件的正确模型是三层，而不是现在的两层直连：

```
回次（原始记录 1~2m，可溯源）
   └─→ 岩体段（完整程度分级单元：归并相邻同性质回次后重算 S、RQD 再判级）
          └─→ 围岩分类段（F.0.2，按桩号/岩体单元）
```

原实现是「一个回次 = 一个完整性分段」直连，缺的正是第 2 步归并——**已按上述三层模型实现**（见 8.4）。归并后同时解决两个问题：短回次样本量小、判级噪声大；长回次跨两种岩体被平均值掩盖。实测样例：21 个 2m 回次（完整/破碎/中等相间 + 一处深度空洞）归并为 5 个岩体段，段界与岩体变化位置吻合。

> 备注：`MainViewModel.MergeAdjacentSegments`（同等级且深度相邻合并）是**先判级后合并**的反向顺序，且挂在已停用的照片分析路径上，已被 `RockMassSegmentBuilder` 取代，随旧绘制模式一并清理。
